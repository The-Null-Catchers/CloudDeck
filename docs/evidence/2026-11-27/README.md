# Local measurement record

Measured source: `2ae580f6bbefabc2b8427d1df90707af6d76cf72`, clean checkout. This later documentation commit stores results; it does not retroactively change their measured source. Application code is unchanged from the local browser-tested revision `95ff51f7e902d7cb066b915c90184327448af2b7`; the intervening commit changes CI runner/JDK/cache settings only.

Environment: local workstation, Linux 7.2.15-4-omarchy x86_64, Intel i5-1035G1, eight logical CPUs, 16,528,609,280 RAM bytes. Node 22.23.5, npm 11.9.0, Go 1.23.12, PostgreSQL server 17.12 with pg_dump/pg_restore clients 18.6, Redis 7.4.2. Docker client 29.9.2 is present but daemon access is denied. Flutter 3.47.6 is CI-only, not part of these local measurements. One API process hosts the normal deployment/notification workers; no live agents. All data and credentials are synthetic. `/tmp` is tmpfs, so these are not physical-disk or VPS measurements.

- `api-burst.json`: four generated servers in a demo workspace, dashboard/fleet read endpoints, one API, 60 measured requests, concurrency four, ten sequential warmups, no deliberate measurement delay. Total measured burst is only 305.413 ms. p50 19.746 ms, p95 26.015 ms, p99 27.638 ms, 196.455 requests/s, zero errors. This short warmed burst is not steady-state capacity, a metrics-query benchmark or SLO evidence. Other synthetic workspaces exist but are not queried by this workload.
- `postgres-recovery.txt`: fixed disposable `clouddeck_recovery` database/role on loopback. One table, 100 rows, one 1,349-byte encrypted backup object. Backup 170.011 ms; restore 40.547 ms. Row/content hash and plaintext/ciphertext checksums are recorded in the raw output. Wrong database credentials and a pre-cancelled restore are rejected; version-1 recovery works after switching the active key to version 2; staging is empty except for the encrypted object. This does not measure mid-restore crash recovery or control-plane RTO.
- `crypto-benchmark.txt`: 8 MiB deterministic incompressible payload, Go benchmark's per-subbenchmark calibration followed by three iterations per sample and three samples. Encrypt 528.82–538.69 MB/s; decrypt 526.05–544.25 MB/s. File sync/removal and tmpfs allocation are included. This is neither a pure AES benchmark nor end-to-end backup/S3 throughput; no unencrypted baseline was measured, so encryption overhead is not isolated.

Reproduce the crypto benchmark from `services/agent` with `go test -run '^$' -bench BenchmarkBackupPayload -benchtime=3x -count=3`. The opt-in PostgreSQL test requires a separately provisioned fixed disposable database and the protected environment variables described in PORTFOLIO_EVIDENCE.md. Run the API script from the repository root with synthetic `CLOUDDECK_BENCH_EMAIL` and `CLOUDDECK_BENCH_PASSWORD`; it accepts only a loopback HTTP API.
